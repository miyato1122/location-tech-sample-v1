# Feature Specification: Nuxtへの移行とライブラリ更新

**Feature Branch**: `002-nuxt-migration`  
**Created**: 2026-04-22  
**Status**: Draft  
**Input**: ユーザー説明: "本プロジェクトをNuxtに移行したい。一度nuxt-appsディレクトリを新規作成して、そこに移行し、問題なければ今のディレクトリ自体も変更する。また、併せて各ライブラリを最新にしたい。特にViteやmaplibre-glはかなり古いため"

## ユーザーシナリオとテスト *(必須)*

### ユーザーストーリー 1 - nuxt-appsディレクトリで動作確認 (優先度: P1)

開発者として、既存のバニラJS + Vite構成のマップアプリケーションをNuxtへ移行した新プロジェクトを `nuxt-apps` ディレクトリに作成し、現行機能（背景地図切り替えなど）がすべて正常に動作することを確認できる。

**この優先度の理由**: 移行の安全性を担保するため、既存ディレクトリを壊すことなくまず試験環境で動作確認することが最優先。

**独立テスト**: `nuxt-apps` ディレクトリ単独で開発サーバーを起動し、地図表示・背景地図切り替え・GSI地形などすべての機能が動作することを確認できる。

**受け入れシナリオ**:

1. **Given** 既存プロジェクトのソースコードがある状態で, **When** `nuxt-apps` ディレクトリにNuxtプロジェクトを作成して開発サーバーを起動する, **Then** ブラウザで地図が正常に表示される
2. **Given** `nuxt-apps` の開発サーバーが起動している状態で, **When** 背景地図切り替えUIを操作する, **Then** 現行の `001-basemap-switcher` 機能と同等の動作が確認できる
3. **Given** `nuxt-apps` の開発サーバーが起動している状態で, **When** GSI地形・不透明度コントロールなど既存機能を操作する, **Then** すべての機能が正常に動作する

---

### ユーザーストーリー 2 - ライブラリを最新バージョンへ更新 (優先度: P1)

開発者として、古くなった `maplibre-gl`（現在 v2.4.0）・`Vite`（現在 v3.2.0）・関連ライブラリをそれぞれの最新安定版へ更新し、最新APIに対応したコードで動作確認できる。

**この優先度の理由**: ライブラリの古さがセキュリティリスクや機能制約につながるため、移行タイミングで同時対応するのが最も効率的。

**独立テスト**: 更新後の `nuxt-apps` で `npm run dev` が正常に起動し、コンソールエラーなしで地図が表示され、すべての既存機能が動作する。

**受け入れシナリオ**:

1. **Given** `nuxt-apps` に最新ライブラリが導入されている状態で, **When** 開発サーバーを起動する, **Then** 廃止予定APIによる警告やエラーが発生しない
2. **Given** 最新の `maplibre-gl` が導入されている状態で, **When** 地図を操作する, **Then** バージョンアップによるAPIの破壊的変更があればコードを修正済みで正常動作する
3. **Given** 最新 Nuxt + Vite 環境で, **When** プロダクションビルドを実行する, **Then** エラーなくビルドが完了しビルド成果物が生成される

---

### ユーザーストーリー 3 - 既存ディレクトリをNuxt構成へ置き換え (優先度: P2)

開発者として、`nuxt-apps` での動作確認が完了した後、既存のプロジェクトルート（バニラJS構成）をNuxt構成に差し替え、単一のプロジェクト構成で継続開発できる状態にする。

**この優先度の理由**: P1の動作確認完了後にのみ実施できる段階的な移行ステップ。

**独立テスト**: プロジェクトルートで `npm run dev` を実行し、`nuxt-apps` で確認した機能と同等の動作が確認できる。

**受け入れシナリオ**:

1. **Given** `nuxt-apps` での動作が確認済みである状態で, **When** プロジェクトルートをNuxt構成に更新する, **Then** ルートから同じ開発・ビルドコマンドが実行できる
2. **Given** ルートがNuxt構成に更新された状態で, **When** 既存のすべての地図機能を操作する, **Then** 移行前と同等の機能が動作する

---

### エッジケース

- `maplibre-gl` v2 → v5 などメジャーバージョンをまたぐ場合のAPI破壊的変更への対応は？
- Nuxtの `ssr: false`（SPA モード）が必要かどうか（maplibre-glはブラウザ環境を前提とするため）
- 既存の `dist/` ディレクトリや `node_modules/` など移行対象外のファイルの扱い

## 要件 *(必須)*

### 機能要件

- **FR-001**: システムは `nuxt-apps` ディレクトリに新規Nuxtプロジェクトを作成しなければならない
- **FR-002**: `nuxt-apps` プロジェクトは、現行プロジェクトが持つすべてのマップ機能（地図表示・背景地図切り替え・GSI地形・不透明度コントロール）を実装しなければならない
- **FR-003**: `maplibre-gl` を最新安定版へ更新し、APIの破壊的変更に対応したコードへ修正しなければならない
- **FR-004**: `Vite`（Nuxt内蔵）を含むすべての依存ライブラリを最新安定版へ更新しなければならない
- **FR-005**: `nuxt-apps` での動作確認完了後、既存プロジェクトルートをNuxt構成に置き換えられなければならない
- **FR-006**: Nuxt移行後もプロダクションビルドが正常に完了しなければならない
- **FR-007**: 移行後の開発サーバー起動コマンドは直感的かつ標準的でなければならない

### 主要エンティティ

- **現行プロジェクト**: バニラJS + Vite 3.2.0、maplibre-gl 2.4.0 ベースの地図アプリ（`index.html`, `main.js`, `style.css`）
- **nuxt-appsプロジェクト**: 移行先の試験用Nuxtプロジェクト（`nuxt-apps/` ディレクトリ）
- **依存ライブラリ**: maplibre-gl, @turf/distance, maplibre-gl-gsi-terrain, maplibre-gl-opacity（各最新安定版）

## 成功基準 *(必須)*

### 測定可能な成果

- **SC-001**: `nuxt-apps` にて開発サーバーが起動後、ブラウザで地図が表示されるまで5秒以内に完了する
- **SC-002**: 現行プロジェクトが持つ全機能（地図表示・背景地図切り替え・GSI地形・不透明度コントロール）が `nuxt-apps` で100%動作する
- **SC-003**: プロダクションビルドがエラーゼロで完了する
- **SC-004**: コンソールに廃止予定APIの警告が表示されない（移行後）
- **SC-005**: 既存プロジェクトルートをNuxt構成に置き換えた後も、全機能が同等に動作する

## 前提条件

- 移行先フレームワークはNuxt（Vueベース）とする
- Nuxtは SSPではなく SPA モード（`ssr: false`）で構成する（maplibre-glのブラウザ前提制約のため）
- `nuxt-apps` ディレクトリはプロジェクトルート直下に作成する
- `nuxt-apps` での動作確認はユーザーが目視で行い、問題なければルート置き換えに進む
- ルート置き換え時は `index.html`, `main.js`, `style.css`, `vite.config.js` などバニラJS固有ファイルを削除してよい
- `dist/` ディレクトリはgitignore対象のため、移行対象外
- ライブラリは `npm` を使用して最新安定版（`@latest`）をインストールする
